# 轨迹对齐算法对比测试报告

## 测试概述

对5种轨迹对齐方法在相同测试数据上进行对比测试，验证各方法的准确性、抗噪声能力和适用场景。

### 测试数据配置

| 参数 | 值 |
|------|-----|
| 轨迹数量 | 300 |
| 样本数 | 2000 |
| 最大偏移 | ±20 samples |
| 噪声标准差 | 0.1 |
| 信号特征 | 正尖峰（~500）+ 负尖峰（~1000） |

---

## 测试结果汇总

| 方法 | 状态 | 原始偏移 (Mean±Std) | 对齐后偏移 (Mean±Std) | 准确率 |
|------|------|---------------------|----------------------|----------|
| **DTW** | ✅ PASS | 10.2 ± 11.9 | 0.0 ± 0.0 | **100%** |
| **SAD** | ✅ PASS | 10.2 ± 11.9 | 0.0 ± 0.0 | **100%** |
| **Peak** | ⚠️ Partial | 144.0 ± 263.0 | 42.2 ± 172.9 | **~70%** |
| **CrossCorr** | ❌ FAIL | 10.2 ± 11.9 | 返回全0 | ❌ |
| **ZC** | ❌ FAIL | 10.2 ± 11.9 | MAE=1.54 | ~60% |

### 失败原因分析

#### CrossCorr 问题 (返回全0偏移)
1. **算法逻辑错误**: 当前使用 `np.argmax(trace_segment)` 找峰值，但信号有正峰(+8)和负峰(-8)
   - `argmax` 找最大值位置，负峰会被忽略
   - 应该用 `argmax(np.abs(trace_segment))` 找绝对值最大位置
2. **窗口问题**: 窗口(450,550)只包含正峰区域附近
   - trace_max_loc 和 ref_max_loc 都在同一窗口内计算相对位置
   - 结果差异被限制在小范围内，算法返回接近0的偏移
3. **验证方法问题**: 验证脚本使用错误的相关性计算方法

#### ZC 问题 (MAE=1.54, ~60%准确率)
1. **噪声敏感**: noise_std=0.1 时噪声产生额外过零点
   - 492个检测到的过零点中大部分是噪声引起
   - 第一个过零点不一定对应实际信号位置
2. **peak_range问题**: 设置了(450,550)窗口但算法只在第一个过零点处对齐
   - 信号在500附近，但零交叉检测可能定位到错误的边沿
3. **算法假设问题**: 假设过零点在固定位置，但随机偏移后可能跨越多个过零点

#### Peak 问题 (~70%准确率)
1. **峰值检测不稳定**: 某些trace有两个峰(正峰+负峰)
   - argmax会选较大的那个，但对齐后位置不对
2. **噪声影响**: 噪声会改变峰值位置
3. **窗口问题**: 需要更精确的峰值搜索窗口

## 各方法详细分析

### 1. DTW (Dynamic Time Warping) - ✅ 最佳

```
原始轨迹: 偏移 Mean=10.2, Std=11.9
对齐后:   偏移 Mean=0.0,  Std=0.0
```

**优点:**
- 完全精确对齐，100%成功
- 视觉对齐效果完美，正负尖峰完全重叠
- 适用范围广

**缺点:**
- 计算量较大，处理速度较慢

**视觉评估:**
- 正尖峰（~500）和负尖峰（~1000）完美对齐
- 所有轨迹重叠度极高

---

### 2. SAD (Sum of Absolute Difference) - ✅ 优秀

```
原始轨迹: 偏移 Mean=10.2, Std=11.9
对齐后:   偏移 Mean=0.0,  Std=0.0
```

**优点:**
- 完全精确对齐，100%成功
- 算法简单，易于理解

**缺点:**
- 对噪声敏感

**视觉评估:**
- 正负尖峰完美重叠
- 背景噪声保持一致

---

### 3. Peak (Peak Detection) - ⚠️ 良好

```
原始轨迹: 偏移 Mean=144.0, Std=263.0
对齐后:   偏移 Mean=42.2,  Std=172.9
```

**优点:**
- 大幅改善，70.7%偏移减少
- 计算快速
- 对清晰单峰信号效果好

**缺点:**
- 约20%轨迹对齐失败（标记✗）
- 对噪声敏感，多峰值时可能选错

**视觉评估:**
- 尖峰对齐良好
- 部分轨迹有轻微残余偏移

---

### 4. CrossCorr (Cross-Correlation) - ❌ 失败

```
原始轨迹: 偏移 Mean=10.2, Std=11.9
对齐后:   偏移 Mean=0.0,  Std=0.0 (所有返回0，未实际对齐)
状态:   [FAIL] - 无实际对齐效果
```

**问题分析:**
1. **算法逻辑错误**: 使用 `np.argmax(trace_segment)` 而非 `np.argmax(np.abs(trace_segment))`
   - 正峰=+8, 负峰=-8，argmax会选择正峰忽略负峰
2. **窗口问题**: 窗口(450,550)只包含正峰区域，trace和ref都在同一窗口计算
   - 相对位置差异被限制在小范围内
3. **实际表现**: 返回所有偏移为0，完全无效对齐

**修复建议:**
- 使用 `np.argmax(np.abs(trace_segment))` 找绝对值最大位置
- 使用真正的互相关计算 `scipy.signal.correlate` 而非简单峰值检测

---

### 5. ZC (Zero-Crossing) - ❌ 失败

```
原始:  偏移 Mean=10.2, Std=11.9
对齐:  MAE=1.54 samples, 准确率~60%
状态:  [FAIL]
```

**问题分析:**
1. **噪声敏感**: noise_std=0.1 在492个检测到的过零点中产生大量虚假过零点
2. **算法假设问题**: 假设第一个过零点对应信号位置，但随机偏移后可能跨越多个过零点
3. **实际表现**: MAE=1.54，约40%轨迹对齐失败

**修复建议:**
- 在检测前添加低通滤波去除噪声过零点
- 使用信号斜率而不仅仅是过零位置
- 设置更精确的搜索窗口

## 结论与建议

### 1. 首选推荐

- **DTW** 或 **SAD**: 对于标准正负尖峰测试数据，这两种方法表现完美，100%对齐

### 2. 按场景选择

| 场景 | 推荐方法 |
|------|----------|
| 复杂波形变形 | DTW |
| 模板匹配 | SAD |
| 清晰单峰信号 | Peak |
| 高噪声环境 | CrossCorr (需修复) |
| 过零点信号 | ZC (需调试) |

### 3. 待改进项

- **CrossCorr**: 需调试互相关峰值检测算法
- **ZC**: 需检查零点检测逻辑或调整参数
